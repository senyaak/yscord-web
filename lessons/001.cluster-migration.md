# 001 — Cluster migration (blue/green)

Move the whole app from one minikube cluster to a new one with minimal downtime,
keeping the data and the old cluster as a fallback until the new one is verified.

Used for real: switching the CNI to Calico (`minikube` → `calico`), then renaming
the cluster (`calico` → `yscord-dev`).

## What "cluster state" consists of

| Part | Example | How it moves |
|---|---|---|
| Manifests in git | `k8s/base`, `k8s/platform`, overlays | `kubectl apply -k` in the new cluster |
| Objects created by hand (not in git) | Envoy Gateway install, `postgres-credentials`, `cloudflared-credentials` | Recreate by hand — **order matters** |
| Data on volumes (PV) | Postgres | `pg_dump` from old → `psql` into new |
| Images loaded into the node | `yscord:dev` | `minikube -p <new> image load` |

Hand-made objects are where migrations surprise you ("who created this, and when?").

## The plan in one picture

```
           ┌── old cluster (blue)  ── cloudflared ──┐
Cloudflare ┤                                        ├─ tunnel "k8s"
           └── new cluster (green) ── cloudflared ──┘
```

Both clusters can connect to the same tunnel. The `cloudflared-credentials`
Secret in the new cluster is the **switch**: without it the new cloudflared pods
cannot start, so no traffic reaches the new cluster until we create it.

## Steps

Set the profile names once (fish):

```fish
set OLD calico
set NEW yscord-dev
```

### 1. New cluster

`minikube start` switches the kubectl context to the new cluster. The old one is
reached with `--context $OLD` from here on.

```fish
minikube start -p $NEW --driver=docker --cpus=4 --memory=4g --cni=calico
kubectl config set-context --current --namespace=yscord
kubectl config get-contexts
```

### 2. Envoy Gateway (hand-made, provides the Gateway API CRDs)

Must come before `k8s/platform`, which uses `GatewayClass` / `EnvoyProxy` types.

```fish
kubectl apply --server-side -f https://github.com/envoyproxy/gateway/releases/download/v1.9.2/install.yaml
kubectl wait --timeout=5m -n envoy-gateway-system deployment/envoy-gateway --for=condition=Available
```

### 3. Platform

cloudflared will hang in `ContainerCreating` (no credentials Secret yet) — intended.

```fish
kubectl apply -k k8s/platform
```

### 4. App (empty database for now)

The namespace must exist before the hand-made Secret.

```fish
kubectl apply -f k8s/base/namespace.yaml
kubectl create secret generic postgres-credentials \
  --from-literal=POSTGRES_DB=yscord \
  --from-literal=POSTGRES_USER=yscord \
  --from-literal=POSTGRES_PASSWORD=(openssl rand -hex 16)
minikube -p $NEW image load yscord:dev
kubectl apply -k k8s/overlays/local
kubectl get pods -w
```

Check the app through Envoy, without the tunnel (port-forward in a separate terminal):

```fish
kubectl port-forward -n envoy-gateway-system svc/envoy-main 8082:80
```
```fish
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: yscord-web.senyaak.work' http://localhost:8082/
```

Expect `200`.

### 5. ⏱ Downtime starts — freeze writes, dump the old database

Scaling the old app to 0 guarantees nothing writes during the dump.
`--clean --if-exists` makes the dump drop tables first (the new DB already has
them from migrations); `schema_migrations` moves along with the data.

```fish
kubectl --context $OLD scale deployment yscord --replicas=0
kubectl --context $OLD exec postgres-0 -- pg_dump -U yscord -d yscord --clean --if-exists > ~/yscord-backup.sql
grep -c '^COPY' ~/yscord-backup.sql
```

### 6. Restore into the new database and compare

Stop the new app so it doesn't write during the restore. `-i` pipes the file into
psql's stdin; `ON_ERROR_STOP=1` aborts on the first error instead of carrying on.

```fish
kubectl scale deployment yscord --replicas=0
kubectl exec -i postgres-0 -- psql -U yscord -d yscord -v ON_ERROR_STOP=1 < ~/yscord-backup.sql
kubectl scale deployment yscord --replicas=1
kubectl rollout status deployment yscord
kubectl --context $OLD exec postgres-0 -- psql -U yscord -d yscord -c "select position, title from queue_item order by position;"
kubectl exec postgres-0 -- psql -U yscord -d yscord -c "select position, title from queue_item order by position;"
```

### 7. Flip the switch — make before break. ⏱ Downtime ends

Turn the new cluster on first, then the old one off.

```fish
kubectl create secret generic cloudflared-credentials -n edge --from-file=credentials.json=$HOME/.cloudflared/85ad9aa4-a71b-4104-b814-4d96b1ad6280.json
kubectl get pods -n edge -w
kubectl --context $OLD scale deployment cloudflared -n edge --replicas=0
```

If the cloudflared pods stay in `ContainerCreating` after the Secret exists, the
kubelet is in mount backoff (up to ~2 min between retries). Delete the pods to
retry now: `kubectl delete pod -n edge -l app=cloudflared`.

### 8. Verify, then remove the old cluster

Open https://yscord-web.senyaak.work — same queue as before?

**Rollback** while the old cluster still exists: scale the old `yscord` and
`cloudflared` back to 1, scale the new `cloudflared` to 0.

Once happy:

```fish
minikube delete -p $OLD
minikube profile $NEW
minikube profile list
kubectl config get-contexts
```

## Gotchas we hit

1. **Secret before namespace**: `namespaces "yscord" not found`. Apply `namespace.yaml` first.
2. **Mount backoff**: pods don't pick up a newly created Secret immediately — delete them.
3. **`grep calico` matched 6 pods**: the node is named after the profile, so control-plane
   pods were `etcd-calico` etc. Filter by labels (`-l k8s-app=calico-node`), not names.
4. **New context's namespace is `default`**: set it to `yscord` right after `start`.
5. **Tunnel DNS**: `cloudflared tunnel route dns` silently uses the tunnel from
   `~/.cloudflared/config.yml`. Pass `--config <empty file> --overwrite-dns`.
6. **Names can't be changed**: neither minikube profiles nor any k8s object name.
   Renaming means creating a new one (this very migration).

## When something hangs

1. `kubectl get pods` — the STATUS says at which stage it is stuck.
2. `kubectl describe pod <name>` — **Events** at the bottom: scheduling, image, mounts, probes.
3. `kubectl logs <name>` (`--previous` after a crash, `-c <container>` for init containers).
4. `kubectl get events -n <ns> --sort-by=.lastTimestamp` — the whole namespace at once.
